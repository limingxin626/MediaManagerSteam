## feat(message): 右侧常驻 Tag Media Panel(Telegram 风格)

### 背景

Message 页(`vue/src/views/Message.vue`)右侧原是一个条件出现的「消息详情」面板(点消息卡片才展开,占半宽,含收藏/编辑/删除/拆分媒体)。需求:改成右侧**常驻**一个 Telegram 风格的 media panel —— 显示**当前选中 tag** 下的所有 media(网格),**左键**点缩略图打开大图预览,**右键**弹菜单可「跳转到对应 message」。

据用户决策:**移除**原「消息详情」面板,由 tag media panel 常驻取代;左键预览 / 右键弹跳转。

### 改动

**后端**

1. **`app/routers/media.py` `get_media_feed`** —— 已有的 `GET /media/feed?tag_id=`(按 `MessageMedia` 展开,Telegram 风格,媒体可重复)在构造 result 时把 `MessageMedia.message_id` 塞进每个 item(改逐行 `model_validate` + `item.source_message_id = mm.message_id`),供「跳转到消息」用。
2. **`app/schemas/media.py`** —— `MediaResponse` 加可选字段 `source_message_id: int | None = None`(默认 None,不影响其它复用该 schema 的端点)。

**前端**

3. **`vue/src/types.ts`** —— `MessageMediaItem` 手写扩展加 `source_message_id?: number | null`(preview 消费 `MessageMediaItem[]`,panel 的 feed item 复用此形状)。
4. **`vue/src/components/TagMediaPanel.vue`(新)** —— 固定宽 `w-72`、`border-l`、竖向 flex(header + 可滚 grid)。`tagId` 为 null 显示占位;`tagId` 变化重置并拉 `/media/feed?tag_id=&limit=40`,底部 sentinel + IntersectionObserver(rootMargin 200px)分页;请求期间 tag 被切换则丢弃结果。3 列方形缩略图(复用 `resolveThumb`/`formatDuration`),视频标记 + 时长。左键 `emit('preview', {items, index})`;右键 `@contextmenu.prevent` 在光标处开轻量 popup 菜单(单项「跳转到消息」),边缘防溢出,点击外部关闭,`emit('jump', source_message_id)`。
5. **`vue/src/views/Message.vue`** ——
   - **移除**整块「消息详情」右侧面板及其独占状态/方法(`selectedMessage`/`selectedMessageLoading`/`splitMode`/`splitSelectedIds`、`handleMessageClick`/`handleDetailToggleStar`/`handleDetailDelete`/`toggleSplitMode`/`handleSplit`/`handleSelectedMessageMediaClick`/`renderDetailText`),并清掉 `onMediaChanged`/`handleMediaDeleted`/`handleMediaRotated`/`handleMediaTagsChanged` 里所有 `selectedMessage` 分支。
   - 左 feed 区宽度改固定 `flex-1`(去掉 `selectedMessage ? 'w-1/2' : 'flex-1'`)。
   - 挂 `<TagMediaPanel :tag-id="selectedTagId" :tag-name="selectedTagName">`;新增 `selectedTagName` computed(从 `tags` 按 id 找)。
   - `@preview` → 复用现有 preview:直接把 `items`/`index` 灌进 `previewItems`/`previewStartIndex` 打开,`currentMessageIndex=-1`(panel 场景不做跨 message 窥视/导航)。
   - `@jump(messageId)` → 首版只处理**当前已加载列表内**:`scrollIntoView` + 用 `highlightMessageId` ref 给对应 `[data-message-id]` 容器套 1.6s `ring-2` 临时高亮;不在列表内 toast「该消息不在当前视图中」(跨页跳转留待迭代)。
   - `MessageCard` 去掉 `@click`(不再打开详情)。清理因移除详情面板而变 unused 的 import(`renderMarkdown`/`resolveUrl`/`resolveThumb`/`formatDuration`)。

### 验证

`cd vue && pnpm build`(vue-tsc 类型检查 + vite 构建)通过,无报错。

后续人工验证清单:右侧 panel 常驻(未选 tag 显示占位)→ 选 tag 加载该 tag 下 media + 滚动分页 → 左键开大图 → 右键弹「跳转到消息」→ 左侧 feed 滚动并高亮对应卡片。

### 跟进:「全部(无标签)」也显示

需求:侧栏选「全部」(`selectedTagId === null`)时 panel 不再显示占位,而是展示**所有 media**。`/media/feed` 的 `tag_id` 本就可选,不传即全部。

`TagMediaPanel.vue` 改动:去掉 `tagId === null` 的占位分支与 `fetchPage`/`reload`/`onMounted` 里的 null 短路;`fetchPage` 传 `tag_id: props.tagId ?? undefined`(null → 省略参数);header 标题 `tagName || '全部媒体'`,计数/空态 guard 去掉 tagId 判断。`tagAtRequest` 仍可为 null,切换丢弃逻辑不变。`pnpm build` 通过。

## feat(message): 页面级卡片网格布局(第三种布局)

### 背景

Message 页此前只有竖排消息流一种页面级布局。原有的 `grid`/`mosaic` 切换(`useMessageLayout.ts`)只控制**卡片内媒体**的排列,不是页面级。需求:加一个**页面级卡片网格** —— 每条 message 变成一张固定大小卡片(封面缩略图 + 文字摘要 + 标签/元信息),规整网格排列。经确认作为**第三种布局**并入现有体系,不替换消息流。

### 改动

1. **`vue/src/composables/useMessageLayout.ts`** —— `MessageLayout` 加 `'card'`;`toggleLayout` 改三态循环 `grid → mosaic → card`(`CYCLE` 数组驱动);`initLayout` 白名单用 `CYCLE.includes` 校验,非法值回退 `grid`。顶部补注释说明两个维度混用一个开关的语义。
2. **`vue/src/components/MessageGridCard.vue`(新)** —— 固定尺寸卡片。封面区 `aspect-[4/3]`,取 `mediaItems[0]`,视频叠播放三角 + 时长,多图右上角 `+N`,无媒体时占位(显示文字或图标)。正文 `line-clamp-2` markdown 摘要;tag chips(最多 3 个,多余 `+N`);底部元信息行(相对时间 + 媒体数)。复用 `resolveThumb`/`isVideo`/`formatDuration`/`renderMarkdown`/`formatRelativeTime` 及 MessageCard 的 IntersectionObserver 淡入写法。Props 取 MessageCard 子集,只 emit `click`(开详情面板)/ `toggle-select`(合并勾选)—— 星标/编辑/删除等操作走详情面板,不在网格卡上堆按钮。
3. **`vue/src/views/Message.vue`** —— 引入 `MessageGridCard`;layout toggle 按钮改三态(当前布局图标 + `layoutToggleTitle` computed 提示下一目标);渲染区按 `messageLayout === 'card'` 分叉:card 态用响应式 grid 容器(`grid-cols-2 sm:3 lg:4 xl:5`)渲染卡片,**保留** `data-message-id`/`data-message-date` 锚点(浮动日期徽标、prefetch、滚动恢复依赖);非 card 态维持原 feed + 行内日期分隔。MessageCard 的 `layout` prop 收窄为 `mosaic|grid`(card 态不渲染它)。首版 card 态不显示行内日期分隔(浮动徽标仍工作)。

### 验证

`cd vue && pnpm build`(vue-tsc + vite)通过,无报错。

后续人工验证:工具栏 layout 按钮循环 grid→mosaic→card;card 态呈响应式规整网格,每卡有封面(视频三角+时长、多图 +N)/摘要 clamp/标签/时间;点卡开详情面板;合并模式可勾选合并;向上滚动无限加载 + 浮动日期更新;刷新后布局记忆(localStorage `message_layout`)。

## refactor: Actor → Collection 重命名 + 新增 People 概念

### 背景

原本并行两套关联系统:**Tag**(标签,与 message/media 多对多)和 **Actor**(演员,与 message 一对多)。需求:把 **Actor 语义改成 Collection**(合集/相册,仍是 message 属于一个 collection 的一对多),并**新增 People**(人物)—— 类似 Mac 相册 App 的「人物」,直接标注在 **media** 上(多对多)。

范围:**backend + Vue**。Mac(`MyNote/`)/ Android(`android/`)本次不动(各有独立 schema 副本,不会立即编译报错,留作后续单独适配任务)。
