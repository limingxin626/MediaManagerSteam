## 修正导入副本的文件日期

- 发现 `shutil.copy2()` 会保留源文件修改时间，但目标副本的 Windows 创建时间是导入时间；仅使用创建时间会把历史媒体错误归到导入日期。
- 文件系统兜底日期规则改为创建/出生时间与修改时间中的较早者：Windows 使用 `min(st_ctime, st_mtime)`，macOS/BSD 使用 `min(st_birthtime, st_mtime)`，Linux 使用 `st_mtime`。
- `repair_media_dates.py` 新增 `--overwrite-existing`，支持 dry-run、修正样例、缺失文件样例、幂等统计；`--apply` 会先通过 SQLite backup API 自动备份数据库。
- focused tests：`14 passed`（`test_media_dates.py`、`test_repair_media_dates.py`、`test_media_date_routing.py`）。
- overwrite dry-run 发现 63 条已有日期需修正、6 条无变化、21 条物理文件缺失；apply 前自动备份为 `Data/db.sqlite3.pre-media-date-rebackfill-20260807-160419.bak`，随后成功修正 63 条。
- 再次 dry-run：0 条需修正、69 条无变化，确认操作幂等。
- 抽查 `20260430_175110_7.png`（Media id=81）：`file_created_at` 已从导入时间修正为 `2023-12-07 16:50:10.537660`。
- 顶层媒体仍为 86 条，其中 68 条可进入时间轴，18 条因物理文件缺失且无 `taken_at` 仍无日期；后端服务已停止。

## Media 页面物理文件过滤

- `/media` 与 `/media/timeline` 新增三态参数 `has_physical_file`：省略返回全部，`true` 返回至少关联一条 `materialize_status='done'` 的 `RepositoryFile` 的逻辑 Media，`false` 返回其余逻辑 Media。
- 查询使用关联 `EXISTS`，避免同一逻辑 Media 有多个物理副本时重复结果或放大时间轴计数；离线仓库保留 catalog，因此仍视为文件存在。
- Media 时间线顶部新增“全部 / 文件存在 / 文件缺失”选择器，过滤变化会重置虚拟网格缓存，并同步作用于 timeline bucket 与分页 items。
- 修复虚拟网格按 DB `created_at` 判断日期桶的问题，改为与后端一致的 `taken_at ?? file_created_at`；`MediaResponse` 补充 `file_created_at` 并重新生成 OpenAPI TypeScript 类型。

- 实例 API 验证：全部 86、文件存在 66、文件缺失 20；存在/缺失无交集，合集与全部完全一致。可进入时间轴的 68 条中，存在 65、缺失 3。
