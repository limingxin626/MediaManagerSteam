## Android 全栈对齐后端 actor→collection 重命名 + 新增 person

### 背景

后端此前做了 `actor→collection` 重命名并新增 `person` / `media_person`(照片人物,多对多)概念,Android 端一直停留在旧 `actor` 模型,导致同步静默丢数据:

- 后端 SyncLog 现在发 `COLLECTION` / `PERSON` 实体类型(不再发 `ACTOR`),Android 增量拉取命中不到分支 → 直接丢弃。
- Message 快照字段从 `actor_id/actor_name` 变为 `collection_id/collection_name`,拉下来后每条消息都丢失合集关联。
- Media 快照新增 `people[]` 数组(`sync.py:128`,`{id,name}`),Android 完全没消费。
- Collection/Person 封面字段是 `cover`,旧代码读 `avatar`。

用户确认:**全量修复**(schema + sync + UI 三层),迁移沿用 `fallbackToDestructiveMigration()`(升版本清库重建)。

先对照后端核实(不猜):全量列表端点为 `GET /collection/sync`(旧 `actors/sync` 已不存在);后端**没有** person 列表端点,Person 只走增量 `/sync/changes`;push 侧 `sync.py:345-360` 接受 `collection_id/actor_id` 别名;media `people[]` 只含 `{id,name}`。

## Android 同步简化:改为设置页手动触发的异步全量同步

### 背景

此前 Android 同步是**全自动**的,通过三条互相独立的路径触发,行为分散、难预测,写操作还会内联等待网络:

1. WorkManager 定期同步(每 15 分钟,仅 WiFi)—— `MainActivity.onCreate` 无条件调度。
2. 网络恢复边沿(`isOnline` false→true)自动触发一次推送 + 重推 PENDING 消息。
3. 每次写操作后内联 `outboxRepository.syncToServer()`(fire-and-forget)—— `MediaRepository` 8 处、`MessageRepository.fireAndForgetSync`。

用户要求:**同步只由用户在设置页手动触发一次,异步执行**。设置页已有「开始同步」按钮(`SettingsViewModel.syncAll()`,跑在 `viewModelScope`,本身已异步),原先只做全量 pull。

### 变更

- `MainActivity.kt`:删除 `schedulePeriodicSync` 调度 + 整段 `networkMonitor.isOnline` 边沿监听(含 `scheduleImmediateSync` + `retryAllPending`);移除 `SyncWorker` / `lifecycleScope` import。
- `MediaRepository.kt`:删除 8 处写操作后的内联 `syncToServer()`(insert/insertList/update/delete/deleteById/deleteAll/toggleStarred/updateRating),入队 outbox 逻辑保留。
- `MessageRepository.kt`:`fireAndForgetSync()` 改为 no-op(保留 `syncNow()` 及 4 处调用点不动,改动面最小)。
- `SettingsViewModel.syncAll()`:全量 pull 之前先跑一次 outbox push(`syncOutboxRepository.syncToServer()`),结果计入汇总(「上传: N 条」);顺序 **push → collection pull → message pull**。
- `MessageListScreen.kt`:移除进入页面时的 `LaunchedEffect { retryAllPending() }` 自动重推(确认:同步只在设置页触发)。
- 删除 `data/service/SyncWorker.kt`(三条自动路径移除后无引用,含其 `sync_prefs` 增量游标逻辑)。

> 取舍:手动同步统一走**全量** `syncFromRemote()`,放弃增量游标。单用户 LAN 场景可接受;后续若要增量再单独把游标持久化移到 `SyncPreferences`。

### 验证

- `./gradlew assembleDebug`:**BUILD SUCCESSFUL**。
- 待人工跑(设备 + backend 8002):写操作后 Logcat 不再有自动 `syncToServer`,后端此时无写入;进设置页点「开始同步」→ outbox 推上后端 + 全量 pull,UI 显示「上传/合集/消息」汇总;app 后台 15 分钟以上无 WorkManager 同步日志。

## Android 手动同步分「增量 / 初始化全量」两个按钮

### 背景

承接上一条「同步改手动」后,用户指出手动入口应细分为两个:**增量同步**(日常,走游标只拉变更)与**初始化全量同步**(首次或游标失效时清库重建)。上一步把增量游标随 `SyncWorker` 一起删了,这里需要把游标逻辑重新引到手动路径。

### 变更

- `SyncPreferences.kt`:新增增量游标 `(server_time, since_id)` 的 `getSyncCursor()` / `setSyncCursor()` / `clearSyncCursor()`,存在原 `sync_preferences` 文件(键 `last_sync_time` / `last_sync_id`)。游标为空 = 尚未初始化。
- `MessageRepository.kt`:新增 `currentServerCursorSeed()` —— 用 `LocalDateTime.now(ZoneOffset.UTC)` + `ISO_FORMATTER_MICROS` 生成对齐后端 `datetime.utcnow().isoformat()`(naive UTC)的时间戳,给全量初始化后 seed 游标用。
- `SettingsViewModel.kt`:`syncAll()` 拆成两个:
  - `syncIncremental()` —— push outbox → 读游标 → `messageRepository.syncIncremental(since, sinceId)` → 持久化新 `server_time` 游标。无游标 → 提示先初始化;410(`NeedFullSync`)→ 清游标 + 提示重新初始化。COLLECTION/PERSON/MEDIA/TAG 变更都走 `/sync/changes`,故增量只需这一条链路。
  - `syncFull()` —— push outbox → 拉取前先记 `currentServerCursorSeed()` → 全量 `collectionRepository.syncFromRemote` + `messageRepository.syncFromRemote` → 再从 seed 起点跑一次 `syncIncremental` 补齐同步窗口内的新变更并拿到后端权威 `server_time` seed 游标(补齐失败则退用本地 seed)。
  - 新增 `hasCursor: StateFlow<Boolean>`,供 UI 判断是否已初始化。抽出 `pushOutbox()` 复用。
- `SettingsScreen.kt`:同步卡片改为两个按钮 —— **增量同步**(主 `Button`,`enabled = 有游标 && 非同步中`)+ **初始化全量同步 / 重新初始化**(次 `OutlinedButton`);描述文案按 `hasCursor` 切换。

### 游标格式对齐(已核实后端,不猜)

`backend/app/routers/sync.py:177` `server_time = datetime.utcnow().isoformat()`(naive UTC,无 `Z`/offset),`:183` 用 `datetime.fromisoformat(since)` 解析。客户端 seed 用 `yyyy-MM-dd'T'HH:mm:ss.SSSSSS` UTC,格式一致;几秒钟的时钟偏差最多让增量重拉个别最近变更(幂等 upsert),无副作用。

### 验证

- `./gradlew assembleDebug`:**BUILD SUCCESSFUL**。
- 待人工跑(设备 + backend 8002):
  - 首次进设置页 → 增量按钮禁用,提示先初始化;点「初始化全量同步」→ 全量落库 + 游标写入,增量按钮变可用。
  - 后端改数据 → 点「增量同步」→ 只拉到该变更,游标推进。
  - 让游标过期(或后端返回 410)→ 增量提示「游标已过期,请重新初始化」,`hasCursor` 归位。

## Android 移除「离线模式」开关

### 背景

同步已全部改为手动触发(增量 / 初始化两个按钮),「离线模式」这个再去 gate 自动同步的开关就成了冗余控制 —— 用户不点按钮本来就不会同步。按用户要求整块移除。

### 变更

- `SyncPreferences.kt`:删除 `isOfflineMode` / `setOfflineMode` / `KEY_OFFLINE_MODE`(及相关 flow import),只保留增量游标 + 滚动锚点。
- `NetworkMonitor.kt`:`isOnline` 不再 `combine(isOfflineMode, isBackendReachable)`,直接等于 `isBackendReachable`(后端可达即在线);构造函数去掉 `syncPreferences` 参数;移除 `combine`/`stateIn`/`SharingStarted` import。
- `SyncOutboxRepository.kt`:删除 `syncToServer` 里的离线模式 skip 分支与 `syncPreferences` 构造参数(保留 `isBackendReachable` 守卫,避免手动推送时 socket 超时挂起)。
- `SettingsViewModel.kt`:移除 `isOfflineMode` / `setOfflineMode` / `isWifiConnected`。
- `SettingsScreen.kt`:删除整张「离线模式」卡片(Switch + 状态文案)及 `Row`/`Switch`/`Alignment` import。
- `DatabaseManager.kt`:`NetworkMonitor(appContext)` / `SyncOutboxRepository(syncOutboxDao, networkMonitor)` 接线同步更新。

> `MessageViewModel` 里发消息仍读 `networkMonitor.isOnline`(现=后端可达)决定即时上传还是存 PENDING_SYNC,语义不变,无需改动。

### 验证

- `./gradlew assembleDebug`:**BUILD SUCCESSFUL**。
- 全局 grep `isOfflineMode|offline_mode` 已无残留。
