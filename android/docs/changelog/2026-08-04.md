# 2026-08-04 开发日志

## Android 全栈对齐后端 actor→collection 重命名 + 新增 person

### 背景

后端此前做了 `actor→collection` 重命名并新增 `person` / `media_person`(照片人物,多对多)概念,Android 端一直停留在旧 `actor` 模型,导致同步静默丢数据:

- 后端 SyncLog 现在发 `COLLECTION` / `PERSON` 实体类型(不再发 `ACTOR`),Android 增量拉取命中不到分支 → 直接丢弃。
- Message 快照字段从 `actor_id/actor_name` 变为 `collection_id/collection_name`,拉下来后每条消息都丢失合集关联。
- Media 快照新增 `people[]` 数组(`sync.py:128`,`{id,name}`),Android 完全没消费。
- Collection/Person 封面字段是 `cover`,旧代码读 `avatar`。

用户确认:**全量修复**(schema + sync + UI 三层),迁移沿用 `fallbackToDestructiveMigration()`(升版本清库重建)。

先对照后端核实(不猜):全量列表端点为 `GET /collection/sync`(旧 `actors/sync` 已不存在);后端**没有** person 列表端点,Person 只走增量 `/sync/changes`;push 侧 `sync.py:345-360` 接受 `collection_id/actor_id` 别名;media `people[]` 只含 `{id,name}`。

### A. Schema 层

- `entities/Actor.kt` → `Collection.kt`:表 `actors`→`collections`,`avatarPath`→`coverPath`。
- 新建 `entities/Person.kt`(表 `people`)、`entities/MediaPerson.kt`(表 `media_people`,复合主键 `[mediaId,personId]`,双 FK CASCADE,镜像 `MediaTag`)。
- `Message.kt`:FK `Actor::class`→`Collection::class`,列 `actorId`→`collectionId`,索引同步。
- `dao/ActorDao.kt` → `CollectionDao.kt`;新建 `dao/PersonDao.kt`(含 media_person 关联读写 + `replaceMediaPeople` 按 mediaId 全量替换)。
- `Relations.kt`:`MessageWithDetails.actor`→`collection`;`ActorWithMessages`→`CollectionWithMessages`;新增 `MediaWithPeople`。
- `AppDatabase.kt`:注册 `Collection`/`Person`/`MediaPerson`,`collectionDao()`/`personDao()`,version `31`→`32`。

### B. Sync 层

- DTO(`SyncModels.kt`/`SyncNetwork.kt`):`RemoteActor`→`RemoteCollection`(`avatar`→`cover`);`RemoteMessage.actor_id/actor_name`→`collection_id/collection_name`;`RemoteMediaItem` 新增 `people: List<RemotePersonRef>?`;新增 `RemotePerson`/`RemotePersonRef`;push DTO `MessageSyncRequest.actor_id`→`collection_id`。
- 端点(`SyncService.kt`):`actors/sync`→`collection/sync`,返回 `RemoteCollection`。
- 拉取 switch(`MessageRepository.kt`):DELETE/UPSERT `ACTOR`→`COLLECTION` + 新增 `PERSON` 分支;MEDIA UPSERT(全量 + 增量)新增 `applyMediaPeople()` —— 解析 `people[]`,不存在的人物先建行,再 `replaceMediaPeople` 写 `media_people`;`parseRemoteActor`→`parseRemoteCollection`(读 `cover`)+ 新增 `parseRemotePerson`;`applyRemoteMessage` 用 `validCollectionIds`。
- Outbox:`SyncOutboxItem.ENTITY_ACTOR`→`ENTITY_COLLECTION` + 新增 `ENTITY_PERSON`;`ActorRepository`→`CollectionRepository`(avatar 下载语义改 cover,目录 `collection_covers`);新建 `PersonRepository`(仅本地读写 + `ENTITY_PERSON` 入队,无全量拉取)。
- `MessageDao.kt`:所有 `WHERE actorId` / `*ByActor*` → `collectionId` / `*ByCollection*`。
- `DatabaseManager.kt`:接线 `collectionRepository`/`personRepository`,`MessageRepository` 构造补 `personDao`。

### C. UI / ViewModel / Navigation

- `ActorViewModel`→`CollectionViewModel`(`ActorGroupItem.avatarPath`→`CollectionGroupItem.coverPath`);`screens/actor/ActorListScreen`→`screens/collection/CollectionListScreen`;`components/ActorCard`→`CollectionCard`。
- `MessageViewModel`:`_actorId/setActorId/getMessagesByActorPaged` → collection 命名;push `actor_id`→`collection_id`。
- `Navigation.kt`:`ACTOR_*` 路由 → `COLLECTION_*`,`MESSAGE_LIST_BY_ACTOR`→`MESSAGE_LIST_BY_COLLECTION`,`filterActorId`→`filterCollectionId`,`BottomNavDestination.ACTORS`→`COLLECTIONS` + 新增 `PEOPLE`;新增 `PERSON_LIST` 路由。
- `MainActivity.kt`:ViewModel 接线 + 路由 + `AppDestinations` 标签「演员」→「合集」并新增「人物」入口 + PERSON_LIST composable。
- 新增 people 入口:`PersonViewModel` + `screens/person/PersonListScreen`(列表页 + 同步落库打通;media 详情展示 people 留作后续)。
- 展示点顺带改名:`MessageCard`/`HomeScreen`(`.actor`→`.collection`)、`MediaViewerScreen`、`CreateMessageDialog`、`CreateGroupDialog`、`SettingsViewModel`(同步文案「演员」→「合集」)。
